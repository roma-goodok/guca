# GUCA — краткий план дальнейших действий

## 1. Зафиксировать материалы

Сохранить как рабочую версию:

- `GUCA interface specification v1.0.md`
- Keynote-макет
- отдельный файл `Ideas for later.md` для новых идей

Не расширять P0 во время первой реализации.

## 2. Быстро проверить макет

Показать главный экран 2–3 людям, которые плохо знают GUCA.

Проверить, понимают ли они:

- где выбрать организм;
- где запустить симуляцию;
- где создать новый геном;
- где добавить новый ген;
- что делают Upload, Download и Share.

Особенно проверить, не путаются ли **New genome** и **Add gene**.

## 3. Создать рабочую копию сайта

1. Сделать fork репозитория `roma-goodok/guca`.
2. Склонировать fork через GitHub Desktop.
3. Открыть проект в Cursor.
4. Создать ветку `interface-redesign`.

## 4. Запустить исходный сайт локально

В терминале проекта:

```bash
npm ci
npm run build
npm run start
```

Проверить, что исходная версия работает до начала изменений.

## 5. Реализовать P0 по частям

Рекомендуемый порядок:

1. Новый layout: верхняя панель, боковая панель, симуляция, нижняя панель.
2. Новый выбор организмов по категориям.
3. Постоянный блок Genome с плитками генов и Add gene.
4. Модальный Genome Editor: Edit gene и New gene.
5. New genome, Upload, Download, Share.
6. Play/Pause, Step, Reset, Speed, 2D/3D, Move/Cut.
7. Перенос существующих настроек в Advanced.
8. About и базовые сообщения об ошибках.

После каждого блока делать отдельный commit.

## 6. Проверять после каждого изменения

Запускать:

```bash
npm run check
npm run build
```

Ручная проверка:

- Dumbbell;
- организм из Evolution;
- организм из LLM;
- Cellular Automaton;
- пустой геном;
- загруженный YAML/JSON;
- 2D и 3D;
- узкое окно браузера.

## 7. Провести тест рабочей версии P0

Дать 4–5 людям задачи:

- выбрать организм;
- запустить и остановить симуляцию;
- выполнить 1 шаг;
- добавить и изменить ген;
- создать, скачать и поделиться геномом;
- найти настройку в Advanced;
- переключиться в 3D.

Исправлять сначала проблемы, которые повторяются у нескольких людей.

## 8. Реализовать P1

После стабильного P0 добавить:

- Auto-pause;
- Unsaved changes;
- tooltips;
- status messages;
- mute/unmute;
- улучшенные ошибки;
- accessibility;
- отдельную проверку телефона и планшета.

## 9. Опубликовать тестовую версию

1. Опубликовать ветку или fork через GitHub Pages.
2. Отправить ссылку владельцу проекта.
3. Приложить макет, спецификацию и список изменений.
4. После согласования создать Pull Request.

## Следующий конкретный шаг

1. Сделать fork.
2. Клонировать проект.
3. Запустить сайт локально.
4. Создать ветку `interface-redesign`.
5. Начать только с нового каркаса страницы, не меняя логику симуляции.
